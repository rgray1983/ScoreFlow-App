### Live Match implementation notes

- Live state is local component state + `scoreflow-live-match-v3`.
- Workspace `MatchRecord` is created at start (`status: live`) and not updated with scores/sets/events/result.
- `activeRecord` only gates setup visibility; its data is not reloaded into live state.
- Created match id is not stored in live state, so later updates cannot target the active match reliably.
- Duplicate/stale CSS remains for old action-wheel class names.

## Rotation Studio audit

Current `RotationPage.tsx` (~626 lines) is an experimental **ghost start→move path editor**.

### Current model (remove as primary architecture)

- Storage key: `scoreflow-rotation-studio-v2`
- Shape: `Record<"R:phase:playerId", { start, move?, server? }>`
- Phases: serve / receive only
- Ghost tokens + single destination path
- Not scoped by org/team/season
- Not integrated with workspace
- No systems, roles, formations, ball, substitutions, or legality
- Flat CSS court (no perspective projection)
- Print/share is prototype-level

### Decision

**Remove the permanent ghost-token model as the product architecture.**  
Keep reusable visuals (fullscreen shell, token styling, team-color accents, roster filtering ideas).  
Rebuild Rotation Studio as a **formation-sequence creator**.

## Duplicate / fragile code

- Court player types duplicated: `CourtPlayer` (Live Match) vs `RotationPlayer` (Rotation Studio)
- Default court coordinates duplicated and incompatible between Live Match and Rotation Studio
- Rotation plans unscoped across teams/seasons
- Live Match undo is not a real undo
- Multiple live workspace match records can accumulate when starting a new match without completing the prior one
