# PR-012 — Fix Live Auth on GitHub Pages

## Status

Ready for local testing and review.

## Branch

`cursor/fix-live-auth-domain-a8ff`

## Purpose

After production Firestore rules shipped, guest live scoring and chat failed on GitHub Pages because Firebase Auth rejected the hosting domain. This change surfaces that error clearly and retries the anonymous session before live writes.

## Scope

- Wait for Auth to be ready and refresh the ID token before live writes.
- Always stamp `ownerId` from `auth.currentUser.uid`.
- Starting a live match from setup now creates a new game instead of writing into a leftover game ID.
- Catch live-create permission errors instead of leaving an unhandled promise.

## Files Changed

- `app.js`
- `service-worker.js`
- `docs/PRs/PR-012.md`

## Implementation Notes

Firestore public reads still work without Auth, which is why the viewer scoreboard appeared while live updates and chat failed. The hosting hostname `rgray1983.github.io` must be added under Firebase Authentication → Settings → Authorized domains.

## Testing Checklist

## Known Limitations

A live game created before Auth succeeded will not update until the scorer has a working anonymous session on the same browser.

## Merge Notes

The console authorized-domain change is required even before this code ships. The app change makes that failure visible and retries the session.
