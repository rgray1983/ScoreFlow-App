# PR-039 — Offline live recovery and court asset optimization

## Status

Ready for Richie to review. One branch / one PR; unmerged and undeployed.

## Branch

`agent/pr-039-offline-recovery`

## Purpose

Keep courtside scores and pending match ends durable through connectivity loss and reload, preserve the shared viewer link, and make the existing court background available offline without its 8.5 MB transfer.

## Scope and files changed

- `src/live/outbox.ts`: one durable latest snapshot per game, owner binding, terminal pending ends, revision-safe acknowledgement and retries. Storage failures are surfaced instead of claiming a save.
- `src/live/syncGame.ts`: Firestore transactions check owner, terminal end, and monotonic revision before writing. A stale request cannot replace a newer acknowledged revision or reopen an ended link.
- `src/state/liveSession.ts`: cached-auth offline startup, local-first queueing, retry on reconnect/focus/auth and every five seconds, reload recovery, latest score during logo compaction, epoch/revision guards, nonblocking pending ends.
- `src/live/recovery.ts`: persist original owner for account-safe recovery; legacy recovery records remain parseable.
- `src/state/workspace.ts`: a replacement match queues the old link's end before resetting locally.
- `src/App.tsx`, `src/ui/LivePill.tsx`: idempotent sync startup and compact Pending / Offline / Online status. Online on the scorer requires queue acknowledgement, not merely browser connectivity.
- `src/live/games.ts`, `src/screens/ViewerPage.tsx`: viewer connection state follows snapshot cache metadata and browser connectivity.
- Queue, transaction and session lifecycle unit tests; original scoring/graphic/timeout tests retained. Old transport-specific session mocks are replaced by tests for the new durable lifecycle and browser flows.
- `e2e/addons.spec.ts`: separate scorer/viewer contexts verify offline rallies, blocked-backend reload, same URL, reconnect, and an offline end delivered after reload.
- `images/scoreboard-bg.webp`, scoreboard CSS, Vite PWA patterns: optimized court image and explicit WebP precaching. Original JPG retained as source artwork.

## Implementation notes

The outbox is versioned in localStorage as `scoreflowLiveOutboxV1`. It coalesces rallies instead of accumulating every score. It keeps owner UID, game ID, complete match state, compact branding, terminal end state and revision. A pending end cannot be replaced by a normal point. Only the same signed-in UID can send it. An acknowledgement removes precisely the sent revision, leaving newer local changes intact. Transactions are retried from the durable outbox instead of relying on in-memory Firestore writes surviving a page reload.

One active scorer/device per game remains the intended model. This is not a multi-device conflict-resolution feature. Browser storage must remain available; private-mode restrictions, clearing site data, or device loss cannot be overcome by local persistence. A first-ever anonymous identity needs a network connection; an already authenticated guest can queue offline. Legacy recovery records without an owner are checked by the server and may require resuming before ending. Existing one-minute timeout timestamps remain absolute, so reconnect does not restart the timer. Highlight age/IDs continue to prevent stale animation replay.

No production rules, data, auth configuration or hosting settings change. Firebase rules still enforce owner UID. No Coach, billing, or visual redesign.

## Performance

Original JPG: **8,545,212 bytes**, 6967×3921.
Optimized WebP: **198,582 bytes**, 2560×1441, quality 86; same composition and artwork. **97.7% smaller** (8,346,630 fewer bytes per uncached court load).

The court image is now in the generated PWA precache (previously excluded by its size). Total precache is about 1,936 KiB with the image included. Initial JavaScript remains about 750 kB minified; route/code splitting is deliberately deferred rather than risking recovery/PWA behavior in this pass.

## Known limitations

LocalStorage cannot survive intentional site-data deletion or a lost device. Multiple devices scoring one game concurrently are out of scope. Physical-device and real-gym validation remain necessary. Transactions add a read per flushed revision; rallies are debounced/coalesced. A lost legacy anonymous Firebase identity cannot regain ownership by claiming its old viewer URL. Original unoptimized source art remains in git, but is not shipped in the Vite bundle.
