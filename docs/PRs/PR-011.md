## Purpose

Replace expired Firebase Test Mode rules with production Cloud Firestore security rules that match the ScoreFlow scoreboard data model, without using `allow read, write: if true` or another expiration date.

## Scope

- Add `firestore.rules`, `firestore.indexes.json`, `firebase.json`, and `.firebaserc`.
- Stamp live games with `ownerId` and give guest scorers/viewers a silent anonymous Firebase session.
- Keep signed-in cloud backup under `users/{uid}`.
- Cover existing ScoreFlow Firestore queries with emulator tests.

## Implementation Notes

The scoreboard already used Firebase Auth for optional cloud backup, but live games, chat, reactions, and presence were written without a UID. Secure owner-only live scoring is impossible without an auth identity, because viewer links expose the game ID. Guest mode now signs in anonymously; the UI still shows Guest Mode until a real account signs in.

ScoreFlow Coach still stores workspace data in `localStorage` and does not use Firestore. Planned Coach collections remain denied by default.

Anonymous Authentication must be enabled in the Firebase console before live sharing works against these rules.

## Known Limitations

- Only the creating scorer session can update a live game. A second device using the scorer URL cannot take over scoring unless it is the same Firebase user.
- Existing in-progress live games that have no `ownerId` are claimed by the next authenticated scorer write after deploy.
- ScoreFlow Coach organization/role permissions are not implemented because that app does not use Firestore yet.
